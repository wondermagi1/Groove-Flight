# Groove Core 击败低频鼓点观察与实现对照

记录日期：2026-11-02。素材为用户提供的授权实机录像。以下是从画面、低频包络和录音瞬态得到的可复现观察，不是参考游戏源码或隐藏参数表。

| 片段 | 起点 | 长度 | 观察目的 |
| --- | ---: | ---: | --- |
| 高密度战斗 A | 12:42 | 24秒 | 多武器和连续击杀 |
| 高密度战斗 B | 17:52 | 28秒 | 大规模敌群和连锁消失 |

## 可测结果

| 片段 | 低频瞬态数 | 每秒低频瞬态 | 中位间隔 | 组内主要间隔 |
| --- | ---: | ---: | ---: | ---: |
| 12:42，24秒 | 96 | 4.00 | 0.133秒 | 约0.13秒 |
| 17:52，28秒 | 122 | 4.36 | 0.133秒 | 约0.13秒 |
| 21:09，30秒 | 138 | 4.60 | 0.139秒 | 约0.13–0.14秒 |

约0.13秒非常接近120 BPM下的十六分音符（0.125秒）。强战斗和Boss段的低频事件密度高于普通底鼓骨架，说明击败/破坏反馈不是只替换原有拍点，而是在音乐骨架上增加事件层。

低频事件没有稳定地全部落在单一120 BPM拍点上；用固定网格拟合时，残差中位约78–123ms。录像混有解说、武器、命中和其他低频层，不能把该残差直接解释为游戏精确调度误差。更可靠的结论是：首下反馈随战斗事件出现，后续短簇按细分拍展开，而不是等待下一次整拍才开始。

## 推断的触发模型

1. 敌人进入死亡状态后立即触发首下低频瞬态，避免等拍造成“打死了但没响”的延迟。
2. 极短时间内连续死亡先聚合，避免同一毫秒叠加出失控音量。
3. 聚合后的击杀簇展开为数下轻击，组内间距接近十六分音符；低频重击不会在每次普通命中都出现。
4. 簇的层数、音高或力度受击杀数量/连杀强度影响，因此连续切队比单杀更有推进感。
5. 武器、命中、击杀和Boss提示拥有不同优先级；低频击杀层不能挤掉受击和危险预警。

## Groove Flight V12 对照实现

- 普通敌人死亡进入45ms聚合窗口。
- 首下在聚合窗口结束时播放，不等待下一整拍。
- 连杀最多展开为4下：底鼓、军鼓、底鼓、踩镲。
- 组内间隔改为125ms，对应120 BPM十六分音符。
- 连杀等级可以进一步提升力度和音高。
- 装甲机保留0和35ms的双层撞击；精英和Boss使用更长的独立反馈。
- 所有击杀鼓均为装饰反馈，不延迟伤害、拾取或受击结算。

## 仍需验证

需要一段“只击杀、无解说、无背景低频”的定向录音，才能进一步确认隐藏采样是否会在同一聚合窗口中随机轮换、是否严格量化到全局十六分网格，以及音高是否按连杀数递增。当前实现基于可听见的事件关系，不声称复刻源码算法。
