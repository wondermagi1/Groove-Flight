# Groove Flight V3：音序、装备与数值执行规则

本文件描述 `scripts/arsenal_loadout.gd` 已实现的纯数据执行层。实际弹体碰撞、角色生命、粒子、音乐输出与UI由游戏层执行；不能仅凭本文件的模型测试认定整场战斗已经验收。

## 装备所有权与音序器

- 三条轨道，每条8格，共24格。库存最多64件独立装备，装备等级上限4。
- 每件装备持有唯一UID，宽度为1、2或3格。宽装备在占用格中重复存储同一个UID；只有最左侧的首格发出事件，属性也只计算一次。
- 装备不能跨越一条轨道的右边界。拖入其他装备的尾格、部分重叠或不够宽的空间会完整拒绝操作。
- 将已装备物品拖入另一物品首格，可在双方宽度均能容纳的情况下交换位置。库存物品不会覆盖或默默挤走已装备物品。
- 卸下保留物品与等级。分解删除该物品的所有格位。选择物品与查看详情不改变装备。

## 作用范围与拍点

规则范围 `all` 作用于全部匹配武器，`row` 作用于同轨匹配武器，`neighbor` 要求两个物品的实际占格边缘相接且在同一轨道。相邻关系按宽度计算，不会穿过空格或跨轨道边界。`target` 可以匹配武器家族或弹道、能量、动力、支援属性。

拍点从玩家可见的第1格开始计算：第1、3、5、7格为奇拍，第2、4、6、8格为偶拍；`first` 为第1格，`final` 为第8格。限定拍点的规则按被影响武器真正发射的那一拍判断。

`stats()` 返回全局、无拍点限制的角色面板属性；针对某行、相邻武器或特定拍点的加成由 `item_stats(uid, serial)`、发射事件的 `stats` 与 `events` 给出。属性来源表保留范围、条件与是否进入全局面板的标记，避免把局部加成显示成所有武器都享有。

## 充能、旋律与复奏

现行生产规则使用2层×8格音序，每格0.125秒，8格一轮1秒。白点和武器触发读取同一 `music.timeline`；每件录音武器只在自己的格触发，且每经过一次该格推进一个本地节拍。四次经过跨越4秒，组成该武器的四拍短语，然后回到第一拍。兼容旧电子武器的隔离测试仍可关闭 `audio_guard_enabled` 后使用三轨四拍模型；这条兼容路径不进入当前商店或实战。状态查询与音频合成不会推进或消耗武器计数。

武器的基础充能为1、2、4或8小节。第 `bar` 小节（从0计）满足 `(bar+1) % charge == 0` 才能发射。充能缩减后，为维持共享循环，将结果向下归入1、2、4、8小节；最低1小节。例如基础8小节受到1小节缩减，最终为4小节，而非7小节。界面应展示实际充能值。

每件武器拥有独立的8音动机和音色ID。动机按实际发射次数推进，静默充能小节不会跳过音符：

```
note_number = max(0, floor((bar + 1) / charge) - 1)
pitch = (weapon.melody[note_number % 8] + weapon_head_slot % 8) % 8
```

改变格位同时改变发射时刻与音高移位。普通复奏产生额外的实际事件，保留音高，略微分散发射角度，最多追加3次。回声驾驶员在本小节末重复最前方武器的半伤害事件；它保留该武器原本发射拍点的条件、充能与音高，不会把首拍加成错误改成尾拍加成，也不会复制仍在充能的武器。

同类连续武器可触发连奏加成；异类连续武器可产生和弦事件。这里的连续要求前一件武器的占格尾部与后一件首格相接。

## 伤害、成长与数值单位

武器单发基础伤害依次乘以：飞船伤害系数、武器等级系数 `1 + .45 × (等级-1)`、属性系数、子弹倍率和规则伤害系数。属性系数为 `max(.1, 1 + 对应主属性 / 100 + 动力 / 200)`。游戏层收到 `event.damage` 后应直接使用，不能再次叠加同一组属性。

支持装备规则的等级系数为 `1 + .35 × (等级-1)`，最高4级为2.05倍。百分比规则使用小数，如 `.15` 表示15%；主属性、护甲、幸运使用数值点。`armor=1` 表示1点护甲，游戏层采用 `damage / (1 + .12 × armor)` 换算，不能当成100%减伤。幸运影响商店稀有度及游戏层掉落机会。

实际限制包括：主属性-90到1000，额外弹数-80到64，子弹倍率0.1到20，暴击率0到95%，暴击伤害1到10倍，最大生命1到250，生命恢复0到25，护甲与幸运0到100，移动加成-75%到200%，吸附倍率0.25到8。负额外弹数会实际减少基础弹数，例如基础3枚受到-1修正后为2枚；最终每次至少发射1枚。发射事件另外限制弹数、穿透、弹速、存续、爆炸范围和复奏次数，以控制异常组合。电弧分支最多8束、光束最多12束、其他弹体最多96枚；装备详情使用相同上限。临时超载和驾驶员增幅在游戏层执行，仍遵守这些发射上限。

事件键支持每小节治疗、冲刺护盾、拾取治疗、击杀爆破、击杀充能、冲刺导弹与击杀治疗。治疗值保留小数。击杀充能修正允许-5到50，负值会减少游戏层的基础5点击杀充能，保留医疗换能器等装备的代价。`events(-1, serial)` 表示当前全局事件规则总和；武器事件的 `events` 包含针对该武器的作用范围。全局周期治疗应由游戏层每小节执行一次，不能在每个支援声音事件中重复发放。

## 商店、合成与分解

商店生成6件不重复商品，第一件固定从当前允许的武器池中抽取，确保每次至少出现1件武器；剩余5件从全部允许商品中抽取，也可能包含更多武器。第1到3波最高稀有，第4到6波开放史诗，第7波起开放传奇。每件候选商品的选择权重为 `1 + rarity × luck × .04`，武器保底位同样应用幸运权重，幸运不会绕过波次开放限制。价格为基础价乘以 `1 + .025 × max(0, wave-1)` 后取整。

购买会校验商品、已售状态、价格、货币与库存容量，成功时返回新UID和确切扣款。货币扣除与已售标志由游戏层负责。失败时库存与音序器均不改变。

两件同ID、同等级物品可以合成一级，最高4级。优先消耗库存副本，再考虑已装备副本。保留玩家选中的UID与格位。因此一件4级物品需8件1级副本。分解返还 `max(1, round(基础价格 × .4 × (1 + .5 × (等级-1))))` 星屑；同一UID不能重复分解退款。

`tests/arsenal_loadout_review.gd` 在Godot4.7.2无界面模式通过1564项检查：252条目结构与规则键、44个武器品质条目的动机与品质曲线、512步兼容周期与查询无副作用、相邻/同轨/家族/奇偶/首尾条件、实际8副本合成、交易失败原子性、库存容量、10个波次共240个种子商店均有可用武器且不越过稀有度限制，以及1600次固定种子的混合宽度移动操作。

`tests/arsenal_combat_review.gd` 另通过124项生产方法检查：44个武器品质条目的实际命中、追踪与穿透、范围伤害、回旋与绕机实体、护甲与移动、暴击与小数恢复、全部7类事件、商店交易回调与最后持有武器回收保护，以及最大13像素弹体的跨网格判定。位置、时间、目标生命和直接调用发射均为明确控制的测试夹具，不等同于自动走完一整局。

这些是模型自动检查结果。生产音频同步、伤害命中、商店UI、完整流程与真人体验需要另外验证。
