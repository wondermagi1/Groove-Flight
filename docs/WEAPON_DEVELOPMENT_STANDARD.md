# 武器开发统一规范（持续维护）

2026-11-09，适用版本 `0.40.0-balance-codex-foundation`。以后新增、重做武器先读本文，再核对[现役特效与音频表](WEAPON_VFX_AUDIO_REFERENCE.md)。本文汇总历次已接受的规则；用户的新决定优先，并须同步更新规范和对应表。

## 已实现的基础

19种现役武器，14种共享羽状质感、17种实体弹、2种激光/电弧。生产目录是 `scripts/arsenal_catalog.gd`，实际发射、运动和绘制分别在 `main.gd`、`weapon_emission.gd`、`weapon_visuals.gd`、`weapon_render.gd`，大范围编排由 `salvo_patterns.gd` 定义。以实际代码和[当前目录快照](data-v40/weapon-selection.json)为准。

| 项目 | 开发约定 |
| --- | --- |
| 类别 | 同类共享材质基础。羽弹沿用鎏金螺旋/尾羽回响体系；导弹、能量珠、环绕体、真激光、电弧保留各自形态。不能把全部类型变成同一种弹体。 |
| 独立运动 | 每颗实体弹拥有实际出膛时差、初速、质量、受力及弯转；群体喷口可以缓慢摇摆，颗粒之间还有差异。首颗在实际发射期限立即出现，其余分布错时；当前大范围编排不超过550ms。 |
| 实际弹道 | 曲线改变位置、速度和碰撞路径。尾迹记录真实经过的位置；不能只画弯曲装饰线，让伤害瞬间落在远方。拒绝尺子一样的多条直线和刚性网格。 |
| 创意发射 | 可设计万花筒、双螺旋、呼吸环、交织、扇形、波纹和非对称喷流；先确定覆盖方向/范围，再把原有弹数分配到分支。不能每加一条分支就重复计算整份弹数。 |
| 发射方向 | 地平线沿机体左右两翼；尾羽回响沿机尾多排U形羽流；七彩折光匣是四斜向U形摇摆羽弹，必须飞行到达后才命中。前向武器保留前向主覆盖。 |
| 光晕/残迹 | 保留局部柔光、清楚的颗粒主体和弯曲残迹；高密度时仍要识别粒子。不同武器以主色、色带、轮廓和发射节奏区分，未来形状变化从材质类别内扩展。不要擅自替换已接受的全体弹头/光晕。 |
| 射程与消逝 | 有效射程内保持完整弹体。达到实际射程后才进入1.5秒缩小、光晕收敛、尾迹消散；退场阶段不再伤害敌人。环绕武器按实际驻留/半径策略处理，不能硬套直射距离。 |
| 命中 | 使用真实弹体的扫掠碰撞和到达时间。激光可以保持直束，电弧保持连接逻辑，不能以“统一质感”为由改成羽弹或反向伪装。 |
| 弹数成长 | 使用 `projectile_growth.gd` 的主属性、品质、精炼共享计算；当前每主属性+1弹、每品质阶+2弹、每精炼级超过1再+1，另加有效改装。按视觉类别上限羽弹256、束128、电弧64。伤害/分支不可再额外乘一次。 |

当前大范围武器行程1850–2400，星冕采用230起的多层扩张半径及惯性中心；具体值读生产编排，不要求未来所有武器都取最大射程。

## 发射、声音和充能是一套事件

普通音序器一轮 **1.5秒/8格**，每格187.5ms；普通敌人仍每0.5秒推进一次，不随充能改变。实际有效充能档为 **1/2/3/4/6/8轮**，等候轮静音；各武器按其占格头部进行判定，占用尾格不重复触发。

一次真实齐射只发一个声音，增加排数、粒子或覆盖方向不增加起音。同种武器不同UID、不同格位独立叠奏。首颗实体弹与声音期限相同。预览、商店、图鉴与实战使用同一充能/音源策略，显式作曲模式保留用户音符与速度。

四档演奏须有触键/运弓、明暗、起音、持音和尾音差异，不能只改音量。1轮用很弱→弱→强→很强；2轮弱→强；3/6/8轮强→很强；4轮很强→强。它们是音频表情，不能恢复已经搁置的四拍伤害循环和武器状态条。

目前十件3/4轮武器的四档资源都是 **0.5秒**；其他实际时长查清单。保留原音高与自然音头，不靠变速或静音补齐伪造时长。未来6/8轮资源须单独设计、试听确认，不能因充能长就默认拉成长音。

音源政策在 `audio/instruments/CHAMBER_PALETTE.json`、`WEAPON_DYNAMICS.json`，实际样本及SHA在两个manifest。重建使用对应 `tools/build_*` 工具，保留导入UID与未涉及的WAV。音量使用既有独立总线，不重启背景音乐，不重置用户音量。

## 后续13种乐器与充能覆盖

统一框架：钢琴；小提琴、中提琴、大提琴、倍大提琴；竖琴；长笛、单簧管、双簧管、巴松；三角铁、钟琴、定音鼓。当前可玩主声部只有钢琴、小提琴、中提琴、大提琴、竖琴；部分竖琴/钢琴重音另含同根音弓弦。其他8类尚未接入，不得把分类名当成已安装音源。

分类按**主音源具体乐器**，不能按伤害属性或“弦乐大类”猜测；复合音色在详情注明伴随声部。新增音源先记录授权、来源、音区、力度层、实际时长和电平，再分配武器。三角铁需显式主类，不借用不相干的GM程序。

后续扩展建议：每个新增乐器先有1轮清楚短句，再配至少一档3/4/6/8轮重音；首批合起来覆盖1、3、4、6、8轮，避免全部武器同频率。具体乐器×回合的缺口以[生产覆盖表](data-v40/run-foundation.json)为准；空白表示待开发，不要求一次填满13×6格或批量复制武器。6轮引擎支持已实现，目前没有基础6轮武器。

## 提交前验收

1. 先上传并核验 `codex/backup-*`，开发在独立 `codex/*`；检查完成的版本也上传并核验。
2. 在生产路径验证1/低弹数/高属性256弹的真实发射、受力、到达伤害、射程及退场；覆盖波次切换、暂停、商店和同种叠奏。计数验证必须区分现存、待发与已退场弹体。
3. 比较图鉴原生WAV和实战渲染，检查静音等待、四档表情、同音高、循环接缝。缓存重复区144秒=96轮，所有当前档位的两次/四次力度乐句须保持相位，加入新档位时重新验证。
4. 在720p/1080p检查界面；在密集敌群下检查实体数量、显存/帧耗时和保留个体的清晰程度。不通过减少真实弹数或敌人数量伪称优化。原生crowd DLL与gdextension须一起发布。
5. 同一提交更新现役对应表、版本/日期/简短修订、生产导出、可点击试听、验证结果；区分已实现、未来方案和历史档案。测试报告要写明模拟条件，不能代替真人听感、胜率或持续60FPS认证。
