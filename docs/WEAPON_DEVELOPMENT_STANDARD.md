# 武器开发统一规范（持续维护）

2026-11-10，适用版本 `0.46.0-clear-combat-ui`。以后新增、重做武器先读本文，再核对[现役特效与音频表](WEAPON_VFX_AUDIO_REFERENCE.md)。本文汇总历次已接受的规则；用户的新决定优先，并须同步更新规范和对应表。

## 已实现的基础

24种现役武器，15种共享羽状质感、18种实体弹、3种激光及3种电链。生产目录是 `scripts/arsenal_catalog.gd`，实际发射、运动和绘制分别在 `main.gd`、`weapon_emission.gd`、`weapon_visuals.gd`、`weapon_render.gd`，大范围编排由 `salvo_patterns.gd` 定义。以实际代码和[当前目录快照](data-v46/weapon-selection.json)为准。

| 项目 | 开发约定 |
| --- | --- |
| 类别 | 同类共享材质基础。羽弹沿用鎏金螺旋/尾羽回响体系；导弹、能量珠、环绕体、真激光、电弧保留各自形态。不能把全部类型变成同一种弹体。 |
| 独立运动 | 每颗实体弹拥有实际出膛时差、初速、质量、受力及弯转；群体喷口可以缓慢摇摆，颗粒之间还有差异。首颗在实际发射期限立即出现，其余分布错时；当前大范围编排不超过550ms。 |
| 实际弹道 | 曲线改变位置、速度和碰撞路径。尾迹记录真实经过的位置；不能只画弯曲装饰线，让伤害瞬间落在远方。拒绝尺子一样的多条直线和刚性网格。 |
| 创意发射 | 可设计万花筒、双螺旋、呼吸环、交织、扇形、波纹和非对称喷流；先确定覆盖方向/范围，再把原有弹数分配到分支。不能每加一条分支就重复计算整份弹数。 |
| 发射方向 | 地平线沿机体左右两翼；尾羽回响沿机尾多排U形羽流；七彩折光匣是四斜向U形摇摆羽弹，必须飞行到达后才命中。前向武器保留前向主覆盖。 |
| 光晕/残迹 | 保留局部柔光、清楚的颗粒主体和弯曲残迹；高密度时仍要识别粒子。不同武器以主色、色带、轮廓和发射节奏区分，未来形状变化从材质类别内扩展。不要擅自替换已接受的全体弹头/光晕。 |
| 射程与消逝 | 有效射程内保持完整弹体。达到实际射程后才进入1.5秒缩小、光晕收敛、尾迹消散；退场阶段不再伤害敌人。环绕武器按实际驻留/半径策略处理，不能硬套直射距离。 |
| 命中 | 使用真实弹体的扫掠碰撞和到达时间。激光可以保持直束，电弧保持连接逻辑，不能以“统一质感”为由改成羽弹或反向伪装。 |
| 弹数成长 | 使用 `projectile_growth.gd` 的主属性、品质、精炼共享计算；当前每主属性+1弹、每品质阶+2弹、每精炼级超过1再+1，另加有效改装。按视觉类别上限羽弹256、束128、电弧64。伤害/分支不可再额外乘一次。 |

编排标称范围1850–2400不是最终结算距离；最终以实际速度×寿命/改装及2400封顶计算，当前旧九件非环绕大范围武器基础实际行程均为2400，万花筒基础2300。星冕采用230起的多层扩张半径及惯性中心。实际碰撞/预览必须同源，不要求未来所有武器都取最大射程。

## V57 角色与Perfect奖励边界

武器弹量先按舰体/天赋/属性等计算，再乘上一段六秒基础成绩与当前Perfect奖励，最高120%，分类硬上限保留。普通Combo不直接提供弹量，Perfect链才逐档奖励。驾驶员只提供读谱/手势/奖励辅助，不能偷偷恢复复射、冲刺加伤、拾取治疗或定时护盾。新天赋只改变战机/武器数值，不改判定和得分。详见[V57](V57_PERFECT_REWARDS_PILOTS.md)。

## V56：歌曲输入和武器齐射分离

歌曲独立生成J/K/L琴块，不由装备数量/充能生成。Perfect100／优秀80／一般40／Miss0（±35/75/140ms）；每6战斗秒三键总得分÷总满分决定下一段全部武器最终弹量，首段100%。数量在现行属性/品质/精炼/舰体/天赋/超载等加成后缩放，按UID/来源轨累计小数；不额外缩放单发伤害、射程、速度、折射/传导。

武器充能仍1.5秒/8格、1/2/3/4/6/8轮，独立映射歌曲音乐点齐射。武器演奏配音、预混支援/底层乐器、图鉴/商店音色试听和自由作曲入口已退出当前游戏。无声PCM只作连续时钟；BGM优先，专属音游击键音后续开发。取消流派过滤，24武器自由混装，3+3商店保留。

本段覆盖下文历史音色开发建议；不得恢复武器四档演奏或给新武器绑定乐器。旧源文件/许可只作历史档案。见[V56](V56_MUSIC_FIRST_REFACTOR.md)与[当前音频政策](../audio/MUSIC_FIRST_POLICY.json)。

## 历史乐器规划（V56已覆盖）

以下保留旧开发背景，当前不继续按武器补音色。新增武器必须先验证歌曲谱面不变、100/80/40/0成绩弹量和零武器配音。

统一框架：钢琴；小提琴、中提琴、大提琴、倍大提琴；竖琴；长笛、单簧管、双簧管、巴松；三角铁、钟琴、定音鼓。当前可玩主声部只有钢琴、小提琴、中提琴、大提琴、竖琴；部分竖琴/钢琴重音另含同根音弓弦。其他8类尚未接入，不得把分类名当成已安装音源。

分类按**主音源具体乐器**，不能按伤害属性或“弦乐大类”猜测；复合音色在详情注明伴随声部。新增音源先记录授权、来源、音区、力度层、实际时长和电平，再分配武器。三角铁需显式主类，不借用不相干的GM程序。

后续扩展建议：每个新增乐器先有1轮清楚短句，再配至少一档3/4/6/8轮重音；首批合起来覆盖1、3、4、6、8轮，避免全部武器同频率。具体乐器×回合的缺口以[生产覆盖表](data-v42/run-foundation.json)为准；空白表示待开发，不要求一次填满13×6格或批量复制武器。万花筒已改4轮；6轮由穹光轮舞提供。

## 提交前验收

1. 先上传并核验 `codex/backup-*`，开发在独立 `codex/*`；检查完成的版本也上传并核验。
2. 在生产路径验证1/低弹数/高属性256弹的真实发射、受力、到达伤害、射程及退场；覆盖波次切换、暂停、商店和同种叠奏。计数验证必须区分现存、待发与已退场弹体。
3. 比较图鉴原生WAV和实战渲染，检查静音等待、四档表情、同音高、循环接缝。缓存重复区144秒=96轮，所有当前档位的两次/四次力度乐句须保持相位，加入新档位时重新验证。
4. 在720p/1080p检查界面；在密集敌群下检查实体数量、显存/帧耗时和保留个体的清晰程度。不通过减少真实弹数或敌人数量伪称优化。原生crowd DLL与gdextension须一起发布。
5. 同一提交更新现役对应表、版本/日期/简短修订、生产导出、当前音频状态/历史来源链接、验证结果；区分已实现、未来方案和历史档案。测试报告要写明模拟条件，不能代替真人听感、胜率或持续60FPS认证。
