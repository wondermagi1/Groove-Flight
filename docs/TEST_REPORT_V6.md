# Groove Flight V6 · MP3识谱验证

2026-10-30，Windows x64、Godot4.7.2、RTX4060 Laptop。正式组件以CPU执行识谱。所有音乐夹具均由测试程序原创合成并实际压缩为MP3，没有使用商业歌曲作为准确率依据。

| 检查 | 结果 | 已验证内容 |
| --- | ---: | --- |
| audio_transcription_review.py |14/14|真实MP3解码、神经模型识别已知旋律/和弦、手动BPM、单声部/多音分轨、网格、截取、自动速度建议，以及参数错误/缺失/损坏/静音文件 |
| audio_import_flow_review.gd |19/19|实际工坊文件路由与参数窗、720p/1080p按钮可见、独立打包组件、原谱保留、结果确认窗、原生试听、确认转入可编辑模型、MIDI导出、取消进程与失败恢复 |
| composer_ui_review.gd |28/28|加入入口后，原有音符编辑、拖动、时值/力度、声部、MIDI文件回调及720p/1080p布局回归 |

原创旋律测试包含已知MIDI音高60、62、64、67、72，识别全部出现，实际得到10个音符；八次预定音在两个位置产生了额外重复音，说明结果仍是需要校正的草稿。多音夹具恢复了同时发声的48、55低音，但没有以此宣称所有伴奏音符准确。6.03秒压缩MP3在实际打包组件中推理/整理约0.315秒，该时间不含进程启动、Godot界面和音频试听准备，也不代表长曲性能。

已查看`docs/screenshots/v6-audio-options.png`与`v6-audio-result.png`：修复了参数说明初始换行造成窗口超高的问题，按钮可见，样式与作曲界面一致。识谱结果不会自动覆盖原作品，试听仍使用游戏原生合成播放链路。

初版单文件打包在受限环境临时DLL解压时失败，最终交付改为目录组件，并补齐解码库CFFI依赖后重新通过整合检查。分辨率检查也改为访问重建后的当前界面，避免测试引用已经释放的弹窗。最终日志无GDScript异常；引擎仍记录系统证书读取及一次OpenGL磁盘缓存写入失败，与本地识谱数据无关。

未进行《发如雪》等商业歌曲或完整真人歌曲的听感/准确率验收。未声称具备歌词识别、歌名识别、人声分离、原曲还原或专业转谱准确度。未重复跑完八行星远征。
