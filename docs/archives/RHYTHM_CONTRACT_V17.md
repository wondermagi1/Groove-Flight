# 音序扫描与武器独立强弱周期：底层约定

确认日期：2026-11-04。依据用户明确要求：“以后所有的底层逻辑就是这套了，即音序器走自己的，武器也要自己走自己的强弱变换。”

本文是当前实现的约束。`0.17.0-independent-groove` 已为当前32把电子武器统一实现1秒扫描与每件武器独立的4秒四拍周期；与早期历史说明存在冲突时，以本约定和用户后续指示为准。

## 两种进度各自维护

- 音序器持续按格扫描并循环。当前实战3轨×8格，每格0.125秒，一轮1秒。
- 每件已装配武器维护自己的强弱拍序与当前进度。不同武器的拍序不能由一个全局强弱计数代替。
- 扫描到武器的起始格时，执行该武器当前拍，并推进到它的下一拍。
- 音序器回到第一格，只重置扫描位置；不能因此把所有武器的强弱拍序重置到第一拍。
- 武器执行完自己的完整拍序后，回到自己的第一拍。

用户再次明确的时间约束：武器不得把自身拍序压缩到一次1秒扫描里。当前启用的电子武器为4拍周期（4秒）；暂时隐藏的录音武器保留其各自周期档案。单拍内按该武器设计同时发射多颗弹丸，不等于推进多个强弱拍。

## 当前武器周期的例子

以扫描首次到达这件武器的起始格为相对0秒：

| 相对时刻 | 音序器行为 | 四拍武器 |
| --- | --- | --- |
| 0秒 | 扫到武器起始格 | 第1拍 |
| 1秒 | 下一轮再次扫到同一格 | 第2拍 |
| 2秒 | 再次扫到同一格 | 第3拍 |
| 3秒 | 再次扫到同一格 | 第4拍 |
| 4秒 | 再次扫到同一格 | 下一组第1拍 |

裂响火弹的对应周期为0秒强拍、1秒弱拍、2秒回到强拍。实弹连奏炮为0—3秒四拍、4秒回到第一拍。时间都从武器所在格首次被扫到开始计算。

另一件武器按自己的起始格和拍序执行。每件武器具体是等强、强弱交替还是其他变化，由对应音源与武器设计确定，不统一强制逐拍渐强。未来武器的拍序长度按实际设计定义；当前炮弹示例为四拍。

## 声音与战斗共同遵守

- 武器的声音、真实发射与强弱表现要对应同一件武器的同一拍，不能声音推进而弹道始终重复第一拍。
- 强弱如何体现为音色、弹数、伤害或其他动作，需要按该武器确定；本约定不擅自指定所有武器的数值曲线。
- 连续原声可以包含一组或多组拍序。允许连续播放，不需要每次扫描到武器都从头重播；但内部事件与发射、下一组的衔接必须对应。
- “各自维护进度”不要求新增彼此漂移的独立计时器；继续以统一音频时钟和音序扫描事件作为调度依据。
- 品质沿用同原型共用原声的现有约定，不能为了品质差异自行改变录音音高或速度。

## 后续实现与验收

后续涉及武器调度、音频、配装、商店试射、作曲试飞或教学的变更，均需核对本约定。生产调度以全局扫描轮次加每件装备的相位偏移计算本地拍序，重编译前根据各自下一拍对齐下一次扫描，连续四轮经历 `0→1→2→3→0`；暂停和恢复共享同一音频时钟，挪格会改变下一次被扫描的时点。

未充能时仍执行本地拍，但伤害和弹数为零。同型号多件按UID保存各自下一拍；挪格保留下一拍，卸下再装备从第一拍开始。普通连音/复奏不会在一轮内推进额外强弱拍；驾驶员echo作为附加回响不推进原武器拍序。具体验证与充能边界见V17_RHYTHM_AND_FEEDBACK.md。
